# 技术设计：Git 暂存管理

## 架构与职责

| 层 | 职责 | 主要入口 |
| --- | --- | --- |
| `winc-editor::git` | 读取真实暂存区；整文件与部分暂存／取消暂存；提交真实 index | 新增 `git/staging.rs`，扩展 `git/commit.rs` |
| `winc-core::diff` | 复用改动块与单行的内容选择算法 | `LineSet`、`Pick`、`pick_changes` |
| `winc-app::app::git` | 操作所属仓库、保存前置、忙碌状态、选择与后台结果 | 新增 `git/commit/staging.rs`，扩展现有提交与差异路径 |
| `winc-app::view` 与输入 | 分组、＋／−、上下文菜单、键盘、差异中的块／行操作 | `view/git/commit.rs`、`view/diff.rs`、现有输入模块 |
| `winc-i18n` | 操作文案、确认、进度与错误 | `en-US/git.ftl`、`zh-CN/git.ftl` |

复用系统 Git、现有信任检查、命令构建、超时、WSL 定位和后台结果投递。新增代码优先放在上述小模块，现有高频上游文件保留调用入口。实际命名随周边结构调整，公开语义以本设计为准。

## 界面与交互

```text
源代码管理                         ⋯
当前仓库 / 分支
┌──────────────────────────────────┐
│ 提交信息                         │
└──────────────────────────────────┘
[ ✓ 提交                          ▾ ]

▾ 合并更改                 1
    conflict.rs            !   打开合并
▾ 已暂存的更改             2      −
    src/app.rs             M      −
    README.md              M      −
▾ 更改                     3      ＋
    src/app.rs             M      ＋
    src/main.rs            M      ＋
    notes.md               U      ＋
```

- 空组沿用现有按内容收起／隐藏规则；有冲突时“合并更改”排在首位。
- 文件行的＋暂存整文件，−取消暂存整文件；组标题的操作处理对应组，目录行处理该目录在所在组中的文件。
- 单击文件打开该组的差异；Ctrl/Cmd、Shift 多选只改变选区。右键菜单提供“暂存所选更改”或“取消暂存所选更改”，复制路径和打开文件沿用现有入口。
- 多选限制在一个组内；从另一组开始选择时以新组作为选区，避免同一路径两侧混合动作。
- 原提交勾选框由即时暂存操作代替；原差异选择控件改为“暂存此块／此行”或“取消暂存此块／此行”。悬停提示始终写明操作。
- 列表的空格键对选中条目执行所在组的暂存／取消暂存，Enter 打开差异，Tab 与箭头沿用现有导航；命令面板提供“暂存全部更改”“取消暂存全部更改”。
- 正在保存或写 Git 时按钮显示忙碌，相关写操作禁用，编辑器和项目切换继续可用。
- “回滚／丢弃”保持独立确认与当前语义，菜单文案明确影响范围；−仅表示取消暂存。

## 状态与条目身份

`git status --porcelain=v2 -z` 仍为分组状态来源。`Entry` 继续持有 `staged`、`unstaged`、`from`，视图投影同一条目到多个组。

文件行、选区、差异标签与后台请求使用 `(仓库根目录, 组/比较类型, 路径)` 标识，避免仅凭路径或状态数组下标区分。重命名还保存原路径；列表刷新后按身份恢复选中项与滚动位置。

差异类型集中定义：

| 类型 | 左侧 | 右侧 | 内容编辑 | 差异动作 |
| --- | --- | --- | --- | --- |
| 已暂存 | HEAD 对应路径 | index 对应路径 | 只读 | 取消暂存块／行 |
| 更改 | index 对应路径 | 当前文档或磁盘 | 沿用工作区编辑 | 暂存块／行 |
| 普通编辑器 Git 比较 | HEAD | 当前文档或磁盘 | 沿用现有能力 | 跳转到明确的暂存比较后操作 |

每次差异请求携带仓库、比较类型、请求序号与相关内容版本。HEAD 不变但 index 变化时也刷新暂存与工作区差异。应用内写操作结束主动刷新，外部操作沿用文件监视与手动刷新入口。

## Git 操作契约

| 操作 | Git 行为 | 保留内容 |
| --- | --- | --- |
| 暂存指定文件 | `git add --all -- <literal paths>` | 其他路径的暂存状态 |
| 暂存全部 | 仓库根目录执行 `git add --all` | 忽略且未跟踪的文件遵循 Git 规则 |
| 取消暂存指定文件 | 有 HEAD 时 `git restore --staged --source=HEAD -- <literal paths>` | 工作区和编辑器内容 |
| 首次提交前取消暂存 | 从 index 移除选定项，使用仅作用 index 的 Git 命令 | 工作区和编辑器内容 |
| 提交 | `git commit --file=- --cleanup=whitespace`，修改上次提交时加 `--amend` | 未暂存改动 |

- 普通暂存提交路径移除 `--only` 与提交时自动加入工作区内容的行为。提交前只检查暂存状态与信息，原有自动保存移到暂存前置阶段。
- 撤销提交仍将变化保留在 index；新分组直接展示其结果。
- 文件路径使用 `relative_all` 的 `:(literal)` 转换，通过参数数组传递。重命名整文件操作覆盖新旧路径，禁止让文件名中的通配符影响其他文件。
- “全部”明确指当前仓库，不限于状态列表前 10,000 项。列表截断时确认文本显示完整仓库范围；需要保存的相关打开文档从编辑器路径集合中取得，避免只遍历截断条目。
- 文件系统保存先完成，之后才进行 Git 写入；同一批次有文件保存失败时停止本批暂存，已经完成的文件保存仍保留。

## 改动块与单行

1. 操作捕获所选比较类型、块／行、源内容版本和 index blob 身份。
2. 暂存时先完成目标文件保存；取消暂存直接使用 HEAD 与 index 快照。
3. 使用保存后的实际内容重新匹配选择。使用 `pick_changes` 组合目标 index 内容：暂存从当前 index 出发应用所选工作区变化；取消暂存从 HEAD 出发保留未被取消的已暂存变化。
4. 以 Git 原生 diff／patch 表示选定变化，使用 `git apply --cached` 的校验与索引锁机制写入；取消暂存可使用反向 patch。复用现有文本选择算法，新增最小 patch 适配能力，避免引入 Git 库或另一套行差异算法。
5. patch 使用 Git blob 的存储形式。展示层经过过滤器的文本先做安全映射，CRLF、BOM 与缺少末尾换行独立处理；自定义过滤器或编码使映射无法确认时只提供整文件操作。
6. 写入前核对相关路径／内容版本，应用 patch 时校验上下文；过期选择、锁冲突或 patch 不匹配返回刷新提示。禁止在失败时自动整文件暂存或覆盖整个 index。
7. 成功后重新读取真实状态和两侧差异，清理本次临时选择。

缺失文件与空文件分开建模。新增文件的部分暂存创建只含所选内容的 index 条目；取消暂存整个新增文件恢复未跟踪状态。删除文件只暂存部分删除时保留剩余 index 内容；完整删除才移除条目。模式、重命名、符号链接和子模块的元数据由整文件操作负责。

## 保存、异步与竞争

```text
动作请求
  → 读取所属项目和仓库
  → 检查写操作忙碌状态
  → 暂存所需文档保存完成
  → 重新检查选择与仓库状态
  → 后台执行 Git 写操作
  → 按发起项目与请求编号收取结果
  → 刷新列表、差异及按钮
```

- 复用 `write_document` 与后台保存等待机制；存在保存前格式化／工具确认时等待相关链完成。需要交互则按窗口交接约定回到发起项目。
- 采用一个暂存请求状态：等待保存、执行 Git、结束；保存失败、项目关闭或仓库切换使尚未启动的续接失效。禁止全局持有不可释放的等待状态。
- `commit.busy`、`branch.running` 与暂存写入互相检查；同一应用中多个项目指向同一工作树时按规范化工作树根目录复用写操作占用，同仓库的不同工作树允许独立暂存。
- 外部 Git 使用 Git 自身索引锁协调。内容版本与 patch 校验处理过期请求，锁文件保持由 Git 管理。
- 后台操作已开始时切换项目不改变其目标；结果通知归属原项目，关闭项目后的 UI 结果沿用现有丢弃规则。
- 完成和失败都刷新 index 相关视图。批量操作返回失败时显示 Git 原因与刷新后的状态，避免假定所有条目都完成。

## 空暂存提交与进行中的操作

- 普通提交无暂存内容且有工作区改动时，确认框使用“暂存全部并提交”，明确包含新文件及当前仓库范围。
- 确认后按保存→暂存全部→提交串行执行。确认后出现新的仓库写操作或范围变化时重新检查，冲突提示优先。
- 暂存成功、提交失败时保留真实 index 和提交信息；重试提交不自动再次加入工作区后续变化。
- 合并／拣选／还原使用当前 index 提交；未解决冲突阻止继续。变基沿用“继续变基”，解决文件由显式暂存入口处理，继续动作保持 Git 原本的空提交等状态规则。
- 修改上次提交仅改信息时允许暂存区无变化，禁止触发普通“暂存全部”的快捷分支。

## 兼容、实施风险与回退

- index 是持久化来源，无需新增配置或状态文件迁移。原勾选状态属于内存状态，移除其参与提交决策的逻辑；草稿、折叠、布局等界面状态继续保留。
- 风险集中于相同路径的多组身份、部分取消暂存、保存后选择变化、Git 内容转换，以及 index-only 变化的差异失效。实施首先用临时仓库覆盖这些契约。
- 部分操作的首期边界是可安全逐行处理的 UTF-8 普通文本；其他内容提供整文件入口和原因说明。
- Windows 本机构建和交互作为本地检查；macOS／Linux／WSL 用可用环境或 CI 检查，结果按平台记录。
- 回退通过还原功能分支的代码提交完成，保留真实 index、工作区与用户草稿；禁止清空暂存区或覆盖工作文件作为回退步骤。

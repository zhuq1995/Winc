# 上游合并技能与自有功能清单

## 目标

为 Winc fork 创建项目技能 `winc-merge-upstream`，在上游检查、合并和合并后回归检查中逐项保留自有功能。

## 要求

- 技能正文负责检查、合并、验收的执行顺序，reference 集中记录全部自有功能、入口、默认值、代码位置和检查要求。
- 功能来源同时覆盖迁移前 `AGENTS.md`、当前代码与 fork 独有提交；将采用上游实现的行为也列入验收。
- 区分行为契约、当前实现和测试缺口；符号存在及编译通过不能代替行为验证。
- 工具文件在 `../Winc-trellis` 的 `chore/trellis-tooling` 分支管理。
- 保留当前应用源代码，技能用只读场景检查验证执行边界。
- 将 AGENTS.md 中整个 Fork 同步区块迁入技能 references，包括分支、工具隔离、合并取舍和本地 Windows 打包步骤；AGENTS.md 保留 Trellis 管理区块。

## 验收条件

- [ ] `SKILL.md` 有明确触发描述，引用 `references/fork-features.md`。
- [ ] 清单覆盖单窗口多项目、打开关闭与提示、项目顺序和名称、真实索引与暂存默认值、复制名称菜单、格式化保存、平台适配、工具隔离与本地打包。
- [ ] 合并前后按稳定功能编号逐项生成证据表，覆盖无冲突文件及默认值变化。
- [ ] 通过技能结构校验和代表场景检查，交付静态审阅报告。
- [ ] AGENTS.md 移除 Fork 同步区块，技能与 reference 的链接指向迁移后的维护及打包文档。

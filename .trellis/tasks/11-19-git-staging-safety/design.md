# 技术设计

## 回滚与动作入口

确认事件携带回滚基准和发起仓库。默认暂存视图用 Git 从索引恢复指定字面路径，只传 --worktree。根据工作区侧变化分类，恢复暂存新增和暂存改名的索引内容。原路径只有在工作区侧改名需要恢复时才参与。真正未跟踪和暂存删除后重建的路径走废纸篓。需要送废纸篓的候选按真实 Git 状态重新核对，无法确认时停止。勾选式使用既有 HEAD 回滚。

右键与键盘动作保留 CommitGroup。共用组内过滤和目录成员映射。放弃全部的可用性与执行采用相同候选条件，排除普通未跟踪和冲突。回滚开始前检查仓库与在途 Git 写操作。确认文案说明恢复基准。

## 暂存与提交

整文件暂存复用保存流程，成功后更新行状态并排队写索引。取消暂存只执行 Git 索引操作。普通提交以真实索引区分直接提交与空索引提示。空索引确认包含未跟踪且未忽略的文件，确认后保存并显式暂存。续接保留仓库和提交并推送／同步意图。确认后重新判断索引状态。保留普通「暂存全部」的已跟踪范围、已有多仓库、amend、继续变基／合并和草稿行为。

## 回归验证

在 winc-editor 用真实 Git 断言底层恢复和字面路径。在 winc-app 用可在 Windows 编译的离屏测试覆盖右键、键盘、状态、确认、磁盘及索引结果。复用测试仓库和废纸篓替身。使用 winc-i18n 检查双语键。更新 Git 暂存规范和 fork 保留清单对应条目。

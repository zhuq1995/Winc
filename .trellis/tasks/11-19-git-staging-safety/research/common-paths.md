# Git 暂存、取消暂存、提交与回滚入口审计

范围为 `dev` 的默认暂存区视图及其共用入口。行为以 `11-10-git-staging` 的 R1–R7、`.trellis/spec/backend/git-staging.md` 和 fork 保留清单 F09–F12 为准。依据当前源码、已有真实仓库用例和本机 Git 2.38 的 `git-restore` 手册；下列回归场景供实施阶段用隔离仓库执行。

## 优先修复

1. **回滚覆写索引。** `Git::rollback` 对跟踪路径执行 `restore --source=HEAD --staged --worktree`，对暂存新增执行 `rm --cached`。共享入口把暂存新增直接送废纸篓；暂存删除后重建时，Git 状态可同时含删除记录与同路径未跟踪记录，按路径筛选会处理两条，送废纸篓后又从 HEAD 恢复旧内容。暂存区模式下，先按请求选择工作区侧，再用字面文件路径执行 `git restore --worktree --`，由 Git 从索引检出；索引中没有对应文件且实际存在的未跟踪／重建文件走已有废纸篓。暂存的新文件属于索引内路径。对已暂存改名后的工作区改动只传实际发生工作区变化的路径，避免把索引已删除的旧路径传给 `restore`。更新中英文确认说明为当前恢复基准。依据 [底层回滚](../../../../crates/winc-editor/src/git/commit.rs#L16)、[共享入口](../../../../crates/winc-app/src/app/git/commit/actions.rs#L642)、[状态解析](../../../../crates/winc-editor/src/git/parse.rs#L403)、[确认文案](../../../../crates/winc-i18n/locales/zh-CN/git.ftl#L320)。
   - 回归场景使用同仓库的 `a`（`HEAD=v1`、`index=v2`、`disk=v3`）、`b`（另有暂存且磁盘不同），从单文件、文件树和标签页分别回滚 `a`。断言 `a` 的磁盘和索引均为 `v2`，HEAD 仍是 `v1`，`b` 三侧原样。另测暂存新增后又编辑、暂存删除后重建、首次提交前的暂存新增，以及已暂存改名后只编辑目标文件。以 `git diff --cached`、`git ls-files --stage` 或 `git show :路径` 检查索引，并在主要用例中提交后断言 HEAD 内容。
2. **整组回滚漏文件，「放弃所有更改」包含仅暂存文件。** `ask_rollback` 优先取 `checked` 文件。默认模式下 `checked` 意为该路径有索引改动，混合组只回滚其中同时存在索引改动的文件。`CommitDiscardAll` 又从所有非冲突且非未跟踪的记录取路径，连纯暂存文件也交给回滚；菜单判定比执行范围还宽，会因仅有冲突而可点。默认模式下让组按钮直接选本组工作区成员，让「放弃所有更改」的启用与执行共用工作区候选条件。保留现有的普通未跟踪文件排除规则，并让暂存删除后重建路径继承受跟踪文件的回滚资格。依据 [组回滚](../../../../crates/winc-app/src/app/git/commit/actions.rs#L594)、[checked](../../../../crates/winc-app/src/app/git/commit/state.rs#L86)、[全部入口](../../../../crates/winc-app/src/app/git/commit/menu.rs#L276)。
   - 回归场景在组中放 `a=MM`、`b=.M`，另有 `c=M.` 和纯未跟踪 `d`。组回滚处理 `a/b`；「放弃所有更改」也仅处理可丢弃的受跟踪工作区改动，`c` 的索引保持，`d` 仍在。只有 `c` 或只有冲突时该全部入口灰显。目录右键另加一个折叠子目录与 `pkg-extra`，断言范围止于所点目录及其工作区组。
3. **右键与键盘丢失分组。** `commit_context_target` 把 `FileIn(i, group)` 降成路径，右键总是包含回滚，多选菜单总是提供两个暂存方向。选 `a=MM` 的已暂存行也能点「暂存」把 `v3` 写入 index。在 `a=MM` 已暂存行与 `b=.M` 更改行混合选择时，在 `b` 的右键菜单点暂存也可顺带把 `a` 的工作区版本写入 index。`Space` 根据路径是否全部暂存决定方向，所以在 `a` 的已暂存行按空格也会暂存 `v3`。`Delete`、`Backspace` 与 `ChangesRollback` 同样拿去重路径直接回滚。将组选中身份传给菜单与键盘动作，再按方向提取该组的精确路径。已暂存行的回滚入口隐藏或不可用，由取消暂存处理。目录／组右键以目标本组成员为范围，避免已有较大选区扩展范围。依据 [右键命中](../../../../crates/winc-app/src/app/input/context_menu/present.rs#L221)、[菜单项](../../../../crates/winc-app/src/app/input/context_menu/menus.rs#L266)、[多选命令](../../../../crates/winc-app/src/app/git/commit/menu.rs#L316)、[键盘](../../../../crates/winc-app/src/app/git/commit/list.rs#L619)、[树与标签菜单](../../../../crates/winc-app/src/app/git/commit/staging.rs#L172)。
   - 回归场景从两组分别右击同一个 `a=MM`，再测已暂存行的空格与删除。取消暂存使 `index=v1`、`disk=v3`，而保留已暂存的操作序列中 `index=v2`。用同目录的 `a=MM`、`b=.M` 与目录外的 `c` 测多选与目录右键；在已暂存组目录只出现取消暂存方向，在更改组目录只出现该组的暂存／回滚方向。文件树与标签页没有组身份，对双侧文件同时提供两种暂存方向，对仅暂存文件只提供取消暂存。
4. **空索引提交偏离 F09，并且只有新文件时无法提交。** `CommitScope::of` 只数受跟踪取 `All(tracked)`，普通提交直接传 `all: true`，执行 `git commit --all`，跳过显式确认且排除未跟踪文件。仅有未跟踪文件时，主按钮的 `blocker` 也会把它当成无内容。最小改法在普通空索引分支统一确认当前仓库的全部非忽略改动，确认后保存相关文档、显式 `git add --all`，再以普通索引提交。取消发生在任何保存或暂存前。提交失败沿用草稿保留，显式暂存结果也保留。非空索引、仅 amend 信息及 Git 进行中的操作保留各自分支。提交并推送／同步需在确认中说清待暂存范围，并把后续操作穿过确认与队列；`git_commit_then` 当前按 `busy` 清后续标志，提交进入暂存队列时也会丢标志。依据 [提交范围](../../../../crates/winc-app/src/app/git/commit/state.rs#L416)、[禁用条件](../../../../crates/winc-app/src/app/git/commit/state.rs#L18)、[普通提交](../../../../crates/winc-app/src/app/git/commit/actions.rs#L416)、[Git 命令](../../../../crates/winc-editor/src/git/commit.rs#L82)、[后续推送标志](../../../../crates/winc-app/src/app/git/commit/menu.rs#L222)。
   - 回归场景由同一 fixture 覆盖首提交仅有未跟踪文件、有提交历史且混合跟踪和新文件、忽略文件、取消确认、拒绝提交的 `pre-commit`。分别断言 HEAD、索引、磁盘和草稿。增加当前已有 `a=v2` 暂存且磁盘为 `v3` 的对照。历史中的 amend、显式启用多仓库提交时其他仓库已有索引但当前仓库没有索引的情况也用对照保护。
5. **整文件暂存直接读磁盘，忽略未保存内容。** 单文件、目录、组、文件树、标签页与命令调用 `stage_paths`，默认直接修改界面状态并排队执行 `git add`。当前文件命令还要求 `status.entries` 已经有 `unstaged`。例如 `HEAD=v1`、磁盘 `v2`、编辑器未保存 `v3`，点任一整文件暂存入口所得索引为 `v2`。暂存路径先完成相关保存及在途保存／格式化，失败或冲突时停止，之后才更新界面和排队。取消暂存路径保持索引专用；对当前标签的命令补上仅缓冲区有改动的入口。依据 [共享暂存](../../../../crates/winc-app/src/app/git/commit/staging.rs#L35)、[当前文件命令](../../../../crates/winc-app/src/app/git/commit/staging.rs#L153)、[已有同步保存](../../../../crates/winc-app/src/app/workspace/files.rs#L598)。
   - 回归场景断言 `v3` 保存完成才写入索引，另测磁盘冲突、在途保存和只有缓冲区改动的 `GitStageFile`。取消暂存的对照为索引退到 `v1`、磁盘 `v2`、编辑器 `v3` 仍为未保存状态。

## 全部范围与现有配套行为

- **状态列表截断。** `GitStageAll`／`GitUnstageAll` 从 `Status::entries` 展开路径，超过 `STATUS_LIMIT = 10_000` 时遗漏后续条目，丢弃全部也有相同问题。`CommitScope::of` 基于同一截断列表，可能在列表前 10,000 条均未暂存而其后有已暂存文件时判为空，继而用 `--all` 覆盖列表外已暂存版本。用完整 Git 状态判定是否有索引改动和生成确认候选，或在支持相同筛选语义时使用仓库级 Git 命令。确认涉及破坏性操作时按完整候选计数。测试用截断视图配合真实索引中隐藏的 `MM` 文件，断言后续提交取 `v2`，磁盘 `v3` 保留。依据 [状态上限](../../../../crates/winc-editor/src/git.rs#L409)、[全量暂存入口](../../../../crates/winc-app/src/app/git/commit/staging.rs#L137)、[提交分支](../../../../crates/winc-app/src/app/git/commit/actions.rs#L453)。
- **各入口当前有意区分。** F10 的 `GitStageAll` 只暂存已跟踪改动。父任务 R5 的「暂存全部并提交」明确包含未跟踪非忽略文件，两者需要独立保持范围。当前界面把普通未跟踪条目单列，目录 ＋／− 依据 `rows.dir(group, dir)`，包括折叠的子目录。「放弃所有更改」目前排除普通未跟踪与冲突，单文件未跟踪回滚则送废纸篓。父任务 R2 与 backend spec 要求把普通未跟踪文件列于「更改」；此差异没有必要通过本次文件回滚修复改变 UI 分组。依据 [F10](../../../../.agents/skills/winc-merge-upstream/references/fork-features.md#L117)、[分组判断](../../../../crates/winc-app/src/app/git/commit.rs#L212)、[目录按钮](../../../../crates/winc-app/src/app/git/commit/press.rs#L266)。
- **正常取消暂存与非空索引提交已有对照。** 取消暂存已有 HEAD 时按路径 `reset`，无 HEAD 时 `rm --cached --force`，两者均保留工作区；暂存改名取消时收集 `Entry::from`。已有目录测试用真实仓库验证目录外索引、同路径磁盘版本与首提交前的取消暂存；已有提交测试用真实仓库验证终端暂存后提交只读索引。树／标签菜单旧用例明确期望纯暂存文件仍显示回滚，需要随契约更新。依据 [取消暂存](../../../../crates/winc-editor/src/git/commit.rs#L106)、[目录回归](../../../../crates/winc-app/src/app/snapshot/directory_staging.rs#L131)、[树／标签和索引提交测试](../../../../crates/winc-app/src/app/snapshot/git/commit/staging.rs#L439)。
- **F12 写操作互斥单列。** 当前暂存队列只属于本 `CommitState`，`stage_paths`、回滚与分支写入口没有共享工作树占用。一次暂存尚未落盘时回滚能并发执行，而且回滚先在界面线程送废纸篓再调 Git。最小保护是共享当前工作树占用，在删除前取得占用，在后台工作结束时释放；阻塞用一个可控后台任务测试「点暂存后立即点回滚」与另一窗口的同仓库操作。F11 的符号链接、块／行和过期选择为独立边界，保留现有跟踪项。依据 [暂存启动](../../../../crates/winc-app/src/app/git/commit/staging.rs#L208)、[回滚使用废纸篓](../../../../crates/winc-app/src/app/git/commit/actions.rs#L660)、[分支操作](../../../../crates/winc-app/src/app/git/branch.rs#L748)、[上游复核表](../../../../.agents/skills/winc-merge-upstream/references/fork-features.md#L233)。

# 修复 Git 暂存与回滚

## 目标

丢弃未暂存内容时保留暂存区，并修复默认暂存区视图中选错文件或版本的常用入口。需求承接父任务 11-10-git-staging。

## 需求与验收

- **R1 回滚以暂存区为基准。** 已提交 v1、已暂存 v2、磁盘为 v3 时，从「更改」回滚后磁盘恢复为 v2，索引仍为 v2，提交得到 v2。暂存新增后修改、暂存改名后修改、暂存删除后重建、无首次提交和字面文件路径遵循同一规则。普通未跟踪文件的单项回滚走废纸篓。缺陷位置和案例见 research/common-paths.md 第 1 项。
- **R2 入口保留组与范围。** 单文件、多选、目录（含折叠子目录）、组标题、键盘和「放弃所有更改」按入口选定的组和范围处理。双组文件的已暂存行执行取消暂存，更改行执行暂存或回滚。文件树和标签页按工作区与索引状态提供动作。批量放弃覆盖受跟踪且有未暂存改动的文件。断言其他路径的磁盘与索引以及取消暂存时的未保存内容。依据审计第 2、3 项。
- **R3 暂存读保存完成后的内容。** 整文件暂存等待操作范围内的未保存内容落盘。失败或冲突时保持索引原状。当前文件命令支持仅有未保存更改的文件。依据审计第 5 项。
- **R4 空索引提交须确认。** 普通提交、提交并推送与同步共用提交范围。空索引且当前仓库有改动时，明确提示会暂存全部非忽略改动，含未跟踪文件。取消时磁盘、索引和草稿保持原状。确认后保存，暂存成功后才提交。提交被拒时保留已暂存内容和草稿。非空索引以索引为版本来源，并继续支持修改上次提交、Git 进行中操作和多仓库提交。依据审计第 4 项。
- **R5 数据与错误检查。** 回滚确认从发起仓库执行，应用内当前仓库有未结束的 Git 写操作时避免开始回滚。用真实 Git 仓库断言索引、磁盘、HEAD 和其他路径的范围。新确认文案覆盖简体中文和英文。

## 范围

默认暂存区和它共用的文件树、标签页、菜单、键盘、命令入口。勾选式的已有回滚模式用于兼容。块与行差异算法、跨窗口写操作协调的全面改造和万级列表批量操作调整是独立议题。空索引提交在状态列表截断时仍须以真实索引判定。

# 单窗口侧栏切换

## 目标

将普通项目集中到同一窗口，通过左侧项目列表切换，减少在多个系统窗口之间切换的操作；界面参考 `reference.png`。

## 背景

- 参考图是局部截图，展示纵向列表、选中项及条目右侧的文字。
- 当前 `Winc` 为每个窗口维护独立的 `App`，包含编辑器、终端和界面状态（`crates/winc-app/src/winc.rs:1`、`crates/winc-app/src/app.rs:677`）。
- 现有侧栏承载文件树、搜索和提交（`crates/winc-app/src/view/workspace/sidebar.rs:35`）；现有目录替换流程会关闭原目录标签和终端（`crates/winc-app/src/app/workspace/session.rs:94`）。
- 现有目录现场包含标签和终端配置，终端中的程序不会在应用退出后恢复（`crates/winc-config/src/state.rs:108`）；`state.json` 目录现场最多 10 份，其他窗口目录最多读取 10 条（`crates/winc-config/src/state.rs:13`、`:355`、`:388`、`:417`）。
- 普通启动会尝试将目标转交给现有进程；`--new-instance`、`--wait` 和标准输入具有独立启动语义（`crates/winc-app/src/cli.rs:3`、`crates/winc-config/src/state.rs:29`）。

## 需求

- R1：普通运行时，同一主进程使用一个系统窗口；最左侧提供独立、常驻的纵向项目列表，右侧保留现有文件树、搜索和提交面板。条目的选中状态参考图片，名称可区分不同项目。
- R2：每个条目保留独立的项目、文档、编辑器和终端状态；切换条目时保留未保存修改，运行中的终端继续执行，后台任务结果回到所属项目。
- R3：打开另一个目录时保留当前项目并新增条目；重新打开已存在的目录时切换到现有条目。新建窗口入口对应创建空白条目。原有 `openFolderInNewWindow` 设置及“此窗口/新窗口”弹窗随新行为调整。
- R4：项目条目可关闭，关闭时沿用现有未保存内容、热退出备份和终端确认规则；关闭最后一个条目后显示开始页。关闭系统窗口及退出时沿用各平台现有语义，并处理全部项目的未保存内容与终端。
- R5：启动恢复遵循现有“启动时恢复上次的目录”设置与数量限制，并兼容旧的 `last`、`otherWindows` 和目录现场数据。
- R6：`--new-instance`、`--wait` 和标准输入继续以独立进程和窗口运行，维持现有命令行语义。普通进程无法转交时沿用独立启动兜底。
- R7：覆盖 Windows、macOS 和 Linux；新增界面文案支持简体中文和英文，保留文件树、搜索、提交、终端和现有文件打开能力。

## 验收标准

- [x] R1：同时打开两个普通项目，系统中该主进程只有一个窗口；项目列表常驻最左侧，当前项清晰高亮，现有面板可同时使用。
- [x] R2：两个项目分别修改文件并启动终端，在两者之间反复切换，标签、未保存修改、光标和终端状态属于各自项目；切走的终端程序持续运行并产生输出。
- [x] R2：后台保存、搜索、文件监视和终端等事件在切换后仍由原项目接收；关闭项目后的迟到事件不会影响其他项目。
- [x] R3：从现有打开入口打开新目录会新增条目；重复打开同一规范化目录会切到已有条目；新建空白条目不关闭已有项目。
- [x] R4：关闭条目时按现有配置处理未保存文件和运行中的终端，取消关闭后项目完整保留；关闭最后一项显示开始页，关闭主窗口或退出会按平台规则处理各项目。
- [x] R5：开启恢复设置时，依据现有上限恢复记录的目录、当前项和对应现场；关闭恢复设置时遵循原有行为。旧状态文件可读取，退出后的终端程序按原有方式处理。
- [ ] R6：特殊启动仍保持独立窗口，`--wait` 等待标签关闭、标准输入读取、`--new-instance` 隔离语义可用。
- [ ] R7：Windows、macOS 和 Linux 的相关代码及两种语言文本保持可构建；项目切换、布局、关闭、恢复及现有关键功能有针对性验证。

## 范围之外

- 跨进程强制全局只存在一个系统窗口。
- 恢复应用退出前运行中的终端进程，或扩大现有目录现场的数量上限。
- 新增项目排序、分组或其他参考图未要求的项目管理功能。

## 实现说明

- 只有一个项目时列表不占位置，界面与原来一样；两个及以上项目时最左侧显示项目列表（宽 190 逻辑像素），条目显示项目名、选中高亮、终端忙时的圆点和悬停时的关闭按钮。
- 窗口和渲染器做成可交接的“外壳”（`crate::winc::Shell`）：切换项目时从旧项目取出、交给新项目，编辑器、终端连接、搜索与后台任务留在原项目里继续运行。
- macOS 关闭窗口改为只隐藏窗口，项目和标签都留在内存里，点程序坞图标原样回来；其他平台关闭窗口仍是退出，退出流程逐个确认各项目的未保存内容与终端。
- 关闭项目（侧栏条目上的 ✕）走 `CloseRequest::CloseProject`：沿用终端确认、热退出备份与目录现场；最后一个项目留在开始页上。
- `openFolderInNewWindow` 仍可读取、不再升级写盘，也不再弹“此窗口/新窗口”提示框；对应四条界面文案已从语言包移除。
- 项目列表超出高度时可用滚轮滚动，绘制与点击区域都裁在列表内；条目右端的 ✕ 关闭项目，“关闭项目”也在项目菜单和命令面板中，只有一个项目时用它回到开始页。
- “保存时格式化”、另存为、工作树移除确认等后台动作结束时需要用户确认的，先由应用层把窗口交给所属项目再显示提示；取消时保留原状。
- 工作树和位置选择器里的其他目录走打开项目的路径，新增条目而不替换当前项目；项目失去窗口时按“离开窗口”处理自动保存。
- 命令行一次给出多个目录时，第一个开在当前项目里，其余各开一个项目；退出确认期间不再新增项目。
- 项目列表使用目录名，目录重名时补上级目录，同一仓库的工作树和同名目录不会显示成一样的条目。

## 已知限制

- R6 的独立窗口行为沿用原有命令行路径，未在本机用真实窗口验证；自动化只覆盖 `Request` 语义。
- R7 的 macOS、Linux 构建与真实窗口交互本机无法验证；Windows 上 `cargo test --workspace` 中 `winc-editor`、`winc-preview`、`winc-pty` 的快照类失败来自本机 `core.autocrlf` 的 CRLF 换行，与本次改动无关。
- 多个空白项目共用 `backups/empty` 备份目录（沿用原有跨进程限制）：正常退出仍逐个询问未保存内容，只有取到锁的项目的草稿能在异常中止后自动恢复。

# 实施计划：单窗口项目切换

## 实施前检查

- [ ] 用户审阅本任务的 `prd.md`、`design.md` 和本计划并明确批准实施后，再运行 `task.py start`。
- [ ] 加载项目开发约定，确认工作区现有改动；以 `research/window-architecture.md` 中的代码入口复核窗口、终端、后台事件和退出路径。
- [ ] 确认 Windows 开发环境和 Rust 工具链；macOS、Linux 检查在对应环境或 CI 中运行。

## 实施顺序

1. [ ] 建立单窗口宿主和独立项目会话的边界；调整窗口、渲染器、平台回调及会话编号的所有权，普通项目不创建额外原生窗口。
2. [ ] 保持每个项目的编辑器、终端连接、搜索、Git 和后台任务状态；让后台事件按项目编号路由，项目切换只更改当前会话，并同步窗口焦点、标题、尺寸和输入法位置。
3. [ ] 增加最左侧项目列表的布局、主题绘制、滚动、命中、选中和关闭操作；与文件树、搜索、提交、编辑区及窄窗口布局协同。
4. [ ] 将目录选择、拖放、最近项目、工作树、命令和普通命令行打开路径接入统一会话操作；处理已打开目录去重、空白条目复用和旧配置项兼容，更新中英文文案。
5. [ ] 接入单项目关闭、全局退出及取消流程；保持热退出备份、终端确认和各平台关闭行为；最后一个项目关闭后显示开始页。
6. [ ] 复用现有 `state.json` 数据与数量限制恢复项目，验证旧数据及恢复设置；保留特殊启动的独立进程、等待和输入行为。
7. [ ] 根据验收标准扩展自动化和截图测试，完成 Windows 实际窗口及终端交互检查，并在可用环境或 CI 中检查 macOS 与 Linux。

## 验证命令

按相关性先运行受影响的测试，再运行仓库要求的检查：

```bash
cargo test -p winc-app
cargo test -p winc-config
cargo test -p winc-pty
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo xtask test --all
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
cargo xtask bench
```

视觉检查运行新增或更新的忽略截图测试，查看亮色、暗色、窄窗口与多项目截图。真实窗口检查覆盖切换时持续运行的终端、未保存文件、切回焦点、重复打开、关闭取消和重启恢复。任何无法运行的平台检查在交付说明中列明。

## 重点检查与回退点

- `crates/winc-app/src/winc.rs`、`app.rs` 和 `app/lifecycle/` 的资源与事件路由改动必须一起检查，避免后台事件投到错误会话或非活动项目停止处理终端。
- `crates/winc-app/src/layout*`、`view/workspace/`、输入处理和两套 `winc-i18n` 资源一起检查，避免绘制与点击区域不一致。
- `crates/winc-config/src/state.rs`、备份及 `main.rs` 的恢复逻辑保持旧文件可读；保留现有数量上限和特殊启动路径。
- 如果宿主改造或跨平台检查出现阻断，保留原始状态文件和现有工作区改动，在解决阻断后继续；不通过清空项目数据或终止终端绕过问题。
